# 05 业务规则

> 规则用**决策表**写，不用流程图。原因：流程图会悄悄漏分支，表格强制穷举所有条件组合，
> 而且没有歧义——人和程序读出来的结论一样。

## 1. 接口权限矩阵

| 接口                                   | 方法              | 需要的权限码                      | 补充规则                             |
| -------------------------------------- | ----------------- | --------------------------------- | ------------------------------------ |
| `/api/auth/login`                      | POST              | 公开                              | 账号不存在/密码错 → 同一句提示       |
| `/api/auth/profile`                    | GET               | 登录                              | —                                    |
| `/api/auth/password`                   | POST              | 登录                              | 新密码 ≥ 8 位，需验原密码            |
| `/api/health`                          | GET               | 公开                              | 不返回连接串等敏感信息               |
| `/api/systems*`                        | 全部              | `system:manage`                   | 超管天然拥有                         |
| `/api/routes`                          | GET               | `route:read`                      | —                                    |
| `/api/routes/my`                       | GET               | 登录                              | 只返回当前用户可见菜单               |
| `/api/routes`                          | POST              | `route:create`                    | —                                    |
| `/api/routes/:id`                      | PATCH             | `route:update`                    | —                                    |
| `/api/routes/:id`                      | DELETE            | `route:delete`                    | 有子路由时拒绝                       |

| `/api/table-configs*`                  | 读/写             | `table:read/create/update/delete` | —                                    |
| `/api/table/:tcid/config`、`data(GET)` | GET               | `data:read`                       | —                                    |
| `/api/table/:tcid/data`                | POST/PATCH/DELETE | 表格配置里的权限码                | 见下表「双层判定」                   |

| 未声明权限的接口                       | —                 | 登录即可                          | 守卫直接放行                         |

## 2. 表格写操作：双层权限判定

「能不能新增/修改/删除一行数据」由**两个条件同时满足**决定：

| 条件 A：表格配置开关        | 条件 B：用户权限          | 结果                                       |
| --------------------------- | ------------------------- | ------------------------------------------ |
| `operations.create = false` | 任意                      | ❌ 403「该表格已关闭新增操作」             |
| `operations.create = true`  | 用户无 `createPermission` | ❌ 403「没有新增权限（需要 data:create）」 |
| `operations.create = true`  | 用户有 `createPermission` | ✅ 允许                                    |
| 超管                        | —                         | ✅ 永远允许（通配权限）                    |

- 默认权限码：`data:create` / `data:update` / `data:delete`
- 可以在配置里改成别的权限码（比如把删除限制成 `data:delete:order`），只要角色里也配了对应码
- 前端返回的 `config.operations.create` 已经是「A && B」的结果，前端不用自己算

## 3. 搜索模式怎么选（给配置者的决策表）

| 场景                         | 建议 searchMode | 理由                                                          |
| ---------------------------- | --------------- | ------------------------------------------------------------- |
| 多个搜索项要「同时满足」     | `AND`           | 最常见，默认值                                                |
| 多个搜索项「满足任一个」就行 | `OR`            | 例如「按订单号或客户名搜」                                    |
| 需要分组、嵌套、取反         | `CUSTOM`        | 例：`(状态 in [已付款,已发货]) OR (金额>1000 AND 不是测试单)` |
| 单条件查询                   | `AND`           | 只有一个条件时 AND/OR 等价                                    |

**运算符可用性约束**（后端强校验，传错直接 400）：

| 运算符               | 只允许的字段类型                   |
| -------------------- | ---------------------------------- |
| `like` / `notLike`   | string / text                      |
| `between`            | number / integer / date / datetime |
| `gt/gte/lt/lte`      | 任意（数据库类型决定行为）         |
| `in` / `notIn`       | 任意（值数组或逗号分隔字符串）     |
| `isNull` / `notNull` | 任意（不需要值）                   |
| `eq` / `ne`          | 任意                               |

## 4. 字段类型映射（配置 → 数据库 → 前端）

| 配置 type  | PostgreSQL 列   | 默认搜索方式 | 前端搜索控件   | 前端表单项   |
| ---------- | --------------- | ------------ | -------------- | ------------ |
| `string`   | `text`          | `like`       | 文本输入       | 单行输入     |
| `text`     | `text`          | `like`       | 文本输入       | 多行文本域   |
| `number`   | `numeric(18,2)` | `between`    | 两个数字输入框 | 数字输入     |
| `integer`  | `integer`       | `between`    | 两个数字输入框 | 整数输入     |
| `boolean`  | `boolean`       | `eq`         | 是/否下拉      | 开关         |
| `date`     | `date`          | `between`    | 日期范围       | 日期选择     |
| `datetime` | `timestamptz`   | `between`    | 日期范围       | 日期时间选择 |
| `json`     | `jsonb`         | `eq`         | 文本输入       | —            |

## 5. 标识符与编码校验规则

| 对象             | 规则                                             | 例子                                     | 违反后果        |
| ---------------- | ------------------------------------------------ | ---------------------------------------- | --------------- |
| 字段名（= 列名） | `^[a-z][a-z0-9_]{0,47}$`，且不在关键字黑名单     | `order_no` ✅、`OrderNo` ❌、`select` ❌ | 400，且不会建表 |
| 物理表名         | `biz_` + TCID 小写，需过标识符校验               | `biz_tdemoorders` ✅                     | 拒绝            |
| TCID             | `T` + 10 位（数字 2~9 + 字母 A~Z）               | `TDEMOORDERS` ✅、`TDEMOORDER0` ❌       | 拒绝            |
| 系统编码         | `^[a-z][a-z0-9_-]{1,31}$`，且不能是 `main`       | `demo` ✅、`Demo` ❌                     | 400             |
| 角色编码         | `^[A-Z][A-Z0-9_]{1,31}$`，且不能是 `SUPER_ADMIN` | `SALES_ADMIN` ✅                         | 400             |
| 用户名           | `^[a-zA-Z][a-zA-Z0-9_]{2,31}$`                   | `zhangsan` ✅                            | 400             |
| 字典编码         | `^[a-z][a-z0-9_]{1,31}$`                         | `order_status` ✅                        | 400             |
| 路由路径         | `^/[A-Za-z0-9_\-/]*$`                            | `/order/list` ✅                         | 400             |
| 自定义页面路径   | `^[A-Za-z0-9_\-/]+\.vue$`                        | `business/examples/demo-table.vue` ✅    | 400             |
| 自定义按钮 value | `^[A-Za-z0-9_-]{1,32}$`                          | `ship` ✅、`标记发货` ❌                 | 400             |

## 6. 必填与空值规则

| 场景                                         | 规则                                                                   |
| -------------------------------------------- | ---------------------------------------------------------------------- |
| 新增数据（超管配了 `required: true` 的字段） | 为空 → 400「字段「xxx」是必填项」                                      |
| 修改数据                                     | 只校验传了的字段；不传 = 不修改                                        |
| 空字符串                                     | 一律存 `null`（不存 `''`），避免「有值但等于空串」的歧义               |
| 数据库列                                     | 全部允许为空（保证 `ADD COLUMN` 不会因为老数据失败）；必填在接口层保证 |
| 搜索条件里的空值                             | 直接忽略该条件（不生成 `status = ''` 这种把结果查空的无效条件）        |
| `decimal` 字段                               | 返回给前端时转成 number（避免前端拿到 Decimal 对象）                   |
| `date/datetime`                              | 返回 ISO 字符串，表格里显示时只截取日期部分                            |

## 7. 菜单可见性规则

一条路由出现在某个用户的左侧菜单里，需要同时满足：

| 条件                                 | 说明                                   |
| ------------------------------------ | -------------------------------------- |
| `sys_route.visible = true`           | 后台里没点「隐藏」                     |
| 属于当前子系统                       | `system_id` 匹配（超管切换后的上下文） |
| 用户有 `permission_code`（如果配了） | 没配则登录即可见                       |
| 请求通过 JWT 验证                    | 未登录一律看不到                       |

> 注意：菜单隐藏 ≠ 接口不可访问。真正的数据保护在接口的权限守卫上。

## 8. 破坏性操作分级

| 操作           | 危险等级 | 影响                                              | 现有保护                                   |
| -------------- | -------- | ------------------------------------------------- | ------------------------------------------ |
| 删除子系统     | 🔴 高    | 连带删除用户/角色/路由/表格配置 + **DROP 物理表** | 主系统禁删；前端二次确认（文案说明会删表） |
| 删除表格配置   | 🔴 高    | **DROP 物理表**，业务数据永久丢失                 | 前端二次确认（文案带物理表名）             |
| 删除用户       | 🟡 中    | 该用户无法登录（历史操作记录不追溯）              | 不能删自己；前端确认                       |
| 删除角色       | 🟡 中    | 角色下有用户时**拒绝**                            | 后端校验用户数                             |
| 删除路由       | 🟢 低    | 菜单消失，页面和数据都还在                        | 有子路由时拒绝                             |
| 删除字典/选项  | 🟡 中    | 引用该字典的下拉框变空                            | 前端确认                                   |
| 改字段类型     | 🔴 高    | 需要重写表                                        | **接口直接拒绝**                           |
| 从配置移除字段 | 🟡 中    | 页面不再显示该列，**数据保留**                    | 返回 `removedFields` 提示                  |
