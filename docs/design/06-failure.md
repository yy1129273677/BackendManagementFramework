# 06 失败模式与应对

> 这份文档回答一个问题：**出错了会怎样？会不会留下脏数据？用户看到什么？怎么恢复？**
> 每一行都是"如果……那么……"，写代码时对照着看。

## 1. 建表 / 改表（DDL 相关）

| 失败场景 | 系统表现 | 是否留脏数据 | 恢复方式 |
|---|---|---|---|
| 字段名非法（如 `select`、`a;drop`） | 400，带中文说明 | ❌ 无（校验在 DDL 之前） | 改名后重试 |
| 字段重复 | 400 | ❌ 无 | 去重后重试 |
| 数据库没有 pgvector 扩展 | `CREATE EXTENSION vector` 失败 → 500 | ❌ 无 | 换 `pgvector/pgvector:pg16` 镜像或手工装扩展 |
| 建表成功但写配置失败 | 500 | ⚠️ 会先 `DROP TABLE` 回滚 | 重试即可 |
| 并发生成同一个小概率 TCID | 第二次插入违反唯一约束 → 500 | ❌ 无（唯一索引挡住） | 重试（生成器会重新取号） |
| 已有表上 `ADD COLUMN` 同名列 | `listColumns` 先查已有列，跳过 | ❌ 无 | — |
| 加字段时数据库连接中断 | 500，配置未更新（先 ALTER 后 UPDATE） | ⚠️ 可能出现"列已加但配置没更新" | 重试 PUT 即可（`ADD COLUMN` 会跳过已存在列） |
| 改字段类型 | 400 直接拒绝 | ❌ 无 | 新建字段代替，人工迁移数据 |

**设计原则**：DDL 只做加法（`CREATE TABLE` / `ADD COLUMN`），不做 `DROP COLUMN` / `ALTER TYPE`。

## 2. 搜索与数据查询

| 失败场景 | 系统表现 | 说明 |
|---|---|---|
| 搜索字段不在配置里 | 400「字段「x」不在表格配置里」 | 防止拿隐藏字段探测数据 |
| 搜索未开启的字段 | 400「字段「x」未开启搜索」 | 同上 |
| 运算符不支持 | 400「搜索方式「x」不支持」 | 白名单校验 |
| 类型不匹配（数字字段传 `abc`） | 400「字段「金额」需要数字」 | 不会变成 `NaN` 去查库 |
| `between` 只给一个值 | 400 | — |
| `filters` 不是合法 JSON | 400「搜索条件格式不正确」 | 不会 500 |
| 空搜索条件 | 不加 WHERE，查全部 | 不生成无效条件 |
| 每页条数传 100000 | 强制压到 200 | 防止一次查询打爆内存/连接 |
| `id` 不是 uuid | 400 | 避免数据库类型错误变成 500 |
| 大表全表扫描（没建索引） | 查询变慢 | ⚠️ **已知限制**：物理表只有主键索引，业务字段没自动建索引。数据量大了要人工加索引（见下节） |

**慢查询兜底**：
- 分页上限 200
- 前端每页条数选项最多 100
- Nginx `proxy_read_timeout 60s`，超过就断，避免连接一直挂着
- 真出现慢查询：`SELECT * FROM pg_stat_statements` 找出来，再 `CREATE INDEX`（业务字段的索引需要人工加，框架不自动建）

## 3. 安全相关

| 失败场景 | 系统表现 | 现有防护 |
|---|---|---|
| 字段名注入（`a"; DROP TABLE x; --`） | 400 | `isValidIdentifier` 正则 + 关键字黑名单 |
| 搜索值注入（`' OR 1=1 --`） | 被当成普通字符串参数查询，查不到数据 | 全部参数化（`Prisma.sql`） |
| 表名注入（伪造 TCID `T;DROP`） | 400 | `physicalTableName` 强制 `^[A-Za-z0-9]{1,32}$` |
| 普通用户伪造 `X-System-Code` 切系统 | 403「只有超级管理员可以切换」 | `SystemContextGuard` |
| 拿 A 系统的角色 id 给 B 系统用户 | 400「角色不存在或不属于当前子系统」 | `user.service` 复合校验 |
| 跨租户读取（猜 TCID） | 404「TCID 不存在或不属于当前子系统」 | 所有查询带 `system_id` |
| 用户枚举（试探哪些用户名存在） | 统一返回「账号或密码错误」 | 登录逻辑 |
| 暴力破解密码 | ⚠️ **当前没有限流** | 已知缺口：生产环境建议在 Nginx 层加 `limit_req` |
| token 被偷 | 8 小时内有效 | 建议 HTTPS；缩短 `JWT_EXPIRES_IN` |

## 4. 认证与会话

| 失败场景 | 系统表现 | 前端表现 |
|---|---|---|
| 未带 token 访问受保护接口 | 401 | 清 localStorage，跳登录页 |
| token 过期 | 401「登录状态已失效」 | 同上，登录后回到原页面 |
| `JWT_SECRET` 被改 | 所有 token 失效（验签失败） | 全员重新登录 |
| 用户被停用 | 已登录的仍可用到 token 过期；重新登录被拒 | 到期后无法登录 |
| 子系统被停用 | 同上 | 同上 |
| 权限被调整 | 已登录的仍是旧权限 | **需要重新登录才生效**（见下） |

**为什么权限不实时**：权限签在 token 里，每个请求不查库。
好处是省一次数据库往返；代价是权限变更有延迟。
如果业务要求"立刻生效"，改法：守卫里按 `user.sub` 查一次 `sys_user + sys_role`（每个请求 +1 次查询）。

## 5. 前端相关

| 失败场景 | 系统表现 |
|---|---|
| 路由配的 `componentPath` 找不到文件 | 显示「自定义页面找不到」提示页（不是白屏），列出排查步骤 |
| TCID 拼错 / 不在当前子系统 | `<Table>` 显示红色错误条「TCID 不存在...」 |
| 没有 `data:read` 权限 | 接口 403，弹出中文错误提示 |
| 插槽名和按钮 `value` 对不上 | 按钮走默认逻辑，弹提示（不报错）——**这是最容易踩的坑** |
| 后端没起 / 数据库挂了 | 请求报错提示；`/dashboard` 的状态卡显示"不可用" |
| 动态菜单没加载出来 | 左侧只有静态管理菜单；守卫会重试一次 |
| 刷新业务页面 | 已修复：`main.ts` 里带 token 时预加载动态路由，不会掉回首页 |
| `npm run build` 报 esbuild 临时目录 `Access is denied` | 受限环境问题，把 `TEMP` 指到可写目录（见 `client/README.md` 常见问题） |

## 6. 部署与数据

| 失败场景 | 表现 | 应对 |
|---|---|---|
| 改了数据库密码但容器起不来 | PostgreSQL 只在数据卷首次创建时读密码 | 备份后 `docker compose down -v` 重建（**会清空数据**） |
| 改了 `.env` 不生效 | 环境变量只在创建容器时注入 | `up -d --force-recreate server`（`update.sh` 已含） |
| 后端启动时 db 还没就绪 | 容器重启循环 | compose 里 `depends_on: service_healthy` + healthcheck |
| 磁盘写满 | PostgreSQL 拒绝写入，接口 500 | 清理日志/旧备份；监控磁盘 |
| 误删子系统 | 配置和物理表都没了 | **只能靠备份恢复**（`pg_dump` 整库） |
| 备份恢复后数据不一致 | 恢复的是整库快照 | 恢复后重启 server 让它重新连池 |
| 内存不足 2G 构建镜像被 OOM kill | 构建中断 | 开 Swap 或本地构建推镜像 |

## 7. 已知缺口（有意先不做，记录在这里防遗忘）

| 缺口 | 影响 | 建议 |
|---|---|---|
| 登录没有限流 | 可被暴力破解 | Nginx `limit_req_zone` + 失败次数锁定 |
| 权限变更不实时 | 需要重新登录 | 改成守卫查库，或用 Redis 存权限版本号 |
| 业务字段没有自动索引 | 大数据量下搜索慢 | 提供「为某字段建索引」的管理功能，或人工建 |
| 没有操作审计日志 | 出问题无法追溯谁改的 | 加 `sys_audit_log`（谁、什么时间、改了什么） |
| `DELETE /api/systems/:id` 的 DROP TABLE 是逐个执行 | 中途失败会留部分表 | 改成收集结果并明确报告哪些表没删掉 |
| 没有软删除 | 删了就没了 | 表格配置可加 `deleted_at` 软删 |
| 前端包体大（1.27MB） | 首屏慢一点 | 按需引入 Element Plus + 路由懒加载（已做页面级懒加载） |
| 没有 E2E 测试 | UI 交互靠手测 | 加 Playwright 覆盖登录→配表→渲染主链路 |
