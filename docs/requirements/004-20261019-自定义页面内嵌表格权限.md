# 需求 004：自定义页面内嵌表格的权限（整理版）

> **来源**：用户 2026-10-19 反馈：
>
> 1. 「假设自定义页面中有引入 table 并写了 TCID，或多个 table TCID，那再分给自定义页面权限时也应能够 增删改查」
> 2. 「每次扫描会比较麻烦，可以这样：路由管理界面中的 JSON 配置里加，如果自定义页面需要哪些 TCID 的权限，就需要在 JSON 中配置 {TCIDS:[]} 这样」
>
> **状态**：✅ 已实现并验证（采用第 2 条方案：配置声明，已移除源码扫描）
> **整理时间**：2026-10-19

---

## 1. 问题

自定义页面（CUSTOM 路由）里可以写一个或多个 `<Table>`：

```vue
<Table :tcid="ORDER_TCID" />
<Table :tcid="'TGOODS0001'" />
```

但路由表里 CUSTOM 路由没有 `tcid` 字段，后端仅凭数据库不知道这个页面用了哪张表，导致：

1. 管理员给用户勾了「自定义页面示例」菜单 → 用户能进页面，但页面里的表格查询 **403**；
2. 权限树里没有对应表格的按钮可勾，管理员没法授权增删改。

---

## 2. 方案：在路由的 JSON 配置里声明 tcids（最终采用）

路由管理 → 编辑路由 → **JSON 配置**：

```json
{
  "title": "订单中心",
  "pageSize": 50,
  "tcids": ["TDEMOORDERS", "TGOODS0001"]
}
```

后端保存路由时（`server/src/route/route.service.ts`）会：

| 处理   | 说明                                                                                                      |
| ------ | --------------------------------------------------------------------------------------------------------- |
| 规范化 | 兼容 `tcids` / `TCIDS` 两种写法，统一存成小写 `tcids`；自动转大写、去重                                   |
| 校验   | 必须是字符串数组、每项形如 `TDEMOORDERS`、最多 50 个；**每项必须属于当前子系统**，否则 400 并指出是哪一项 |
| 读取   | `declaredTcids(config)`（`server/src/route/route-tcids.ts`，纯函数 + 单测）供权限树和读权限使用           |

据此实现：

| 能力         | 说明                                                                                |
| ------------ | ----------------------------------------------------------------------------------- |
| 读权限       | 勾了这个自定义页面的菜单 → 页面里 `tcids` 声明的表都能读（`table-data.service.ts`） |
| 增删改       | 页面菜单节点下面会挂 `tcids` 中每张表的新增/修改/删除/自定义按钮，可单独勾          |
| 页面节点说明 | 权限树里这个菜单会显示「页面内嵌表格：订单列表」                                    |

> 权限树结构保持「菜单下面挂按钮」，前端角色页 el-tree 开了 `check-strictly`（父子不联动），
> 所以勾/取消某个按钮只影响该按钮，不会把菜单变半选、也不会丢菜单权限。
> 同一张表被多个入口引用时按钮会在各入口各出现一份（指向同一个权限码），保存时按码去重。

> 为什么不继续用「构建时扫描源码」：
> 每次改自定义页面都要重跑 `npm run scan:view-tables` 并提交生成文件，太麻烦且容易忘。
> 配置声明零构建步骤、可精确控制（包括动态 tcid），代价是「改了页面要顺手改配置」。
> 两者只能选一个，按用户要求选了配置声明，扫描脚本与生成文件已全部删除。

## 5. 使用约定

1. 自定义页面里新增/删除 `<Table :tcid>` 后，**到「路由管理 → 编辑该自定义页面 → JSON 配置」同步改 `tcids`**。
2. 「插入 tcids 模板」按钮会补上 `"tcids": []`，保留已有配置，不会覆盖。
3. 只写 `tcids` 不写别的也行：`{"tcids": ["TDEMOORDERS"]}`。
4. 读权限只要求菜单；`tcids` 不会自动给写权限——增删改仍需在页面菜单下面勾选对应按钮。

---

## 6. 明确不做 / 边界

| 不做                           | 原因                                                      |
| ------------------------------ | --------------------------------------------------------- |
| 运行时让前端上报用了哪些表     | 需要信任前端上报（可伪造），权限判断不能依赖客户端        |
| 继续扫描源码自动生成映射       | 用户明确说每次扫描麻烦；配置声明更可控                    |
| 在 `sys_route` 加 `tcids` 字段 | 要改表结构 + 迁移；`config` JSON 本来就是这个用途，零迁移 |
| 声明 `tcids` 就自动给写权限    | 违反最小权限原则，写权限必须显式勾选                      |
