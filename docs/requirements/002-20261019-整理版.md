## 2. 我的理解（拆成可验收的点）

### 需求 1：图标选择器

- 路由编辑弹窗里的「图标」不再是输入框/一行一个图标的下拉，改成一个**弹层网格**：一行 6 个，直接显示图形 + 图标名，可搜索，点一下选中。
- 图标来源：Element Plus 内置图标（`@element-plus/icons-vue`，约 290 个），因为现在菜单图标就是按名字存、用 `<component :is="name">` 动态渲染的。
- 数据库字段不变，仍然存图标名字符串。

### 需求 2：权限改成「菜单 + 按钮」的树

- 路由管理里**去掉手填「访问权限码」输入框**（这就是"意义不明确"的来源）。
- 路由新增「访问控制」：**公开（登录即可见）/ 按角色（要在权限树里勾）**。
- 角色编辑弹窗右侧改成一棵 `el-tree`，结构：
  - 系统功能（用户/角色/字典/表格配置等管理能力，沿用现有权限码）
  - 菜单与按钮
    - 订单管理（菜单节点）
      - 新增（订单列表）
      - 修改（订单列表）
      - 删除（订单列表）
      - 标记发货（自定义按钮）
- 勾选即授权：菜单节点对应权限码 `menu:<routeId>`（系统生成，不用人填）；表格按钮节点对应表格配置里的按钮权限码。
- 新增表格配置时，按钮权限码默认**按 TCID 生成**（`data:create:TORDER` 这种），这样"A 表的新增"和"B 表的新增"是两回事。

### 需求 3：路由上的 JSON 配置下发到前端

- 路由新增 `config`（JSON），后台用文本域编辑，保存前校验 JSON 合法性，支持一键格式化。
- 前端渲染动态路由时通过 **props** 注入：自定义页面里 `defineProps<{ routeConfig?: any }>()` 就能收到。
- 用途举例：默认筛选值、页面标题、列宽、开关某个功能，**不用改代码发版**。

### 需求 4：内容区顶部页签

- 右侧内容区顶部加一排 tag（在页面标题栏下面）：访问过的页面自动出现，点 tag 切换，× 关闭。
- 首页固定不可关；关掉当前页签时自动跳到右侧/左侧相邻页签；支持「关闭其它 / 关闭全部」。

### 需求 5：字段级「表单配置」

- 「编辑表格配置」弹框加宽（1180 → 1400）。
- 字段列表每行新增：**列表排序**、**搜索条件排序**；「字典编码」从手填改成**下拉选择**（数据来自业务字典类型列表）。
- 每行加一个 **「表单配置」按钮**，点击弹**二级弹框**，配置该字段：
  - 表单排序（默认与列表排序相同）
  - 是否显示
  - 所占列（24 栅格制：24=整行，12=一半，8=三等分）
  - 是否必填
  - 验证规则：正则（内置手机号/邮箱/身份证/正整数/网址/邮编，也可自定义）+ 自定义联动校验
- 表格组件 `<Table>` 相应支持：列顺序按列表排序、搜索项按搜索排序、表单按栅格布局 + 表单排序 + 校验。

## 3. 需要你拍板的 6 个点（都给了推荐答案）

> 这几处是我实现时必须做取舍的地方，写清楚给你选。**你不回复，我就按「推荐」执行。**

### ① 是否所有菜单都必须勾选才能看？（推荐：不是，用「公开/按角色」两种）

如果"所有菜单都要勾选"，现在 demo 子系统的菜单会立刻对普通用户消失，需要先去角色里点一遍。所以我加了开关：默认**公开**（保持现状），需要控制的菜单改成**按角色**。

- **A. 公开 / 按角色 两种（推荐）** —— 兼容现状，改动小
- B. 全部必须勾选 —— 更严格，但要给现有角色补一次权限

### ② 表格按钮权限码是否按表隔离？（推荐：是，但老数据不动）

新建的表格默认用 `data:create:<tcid>`；已有表格（如 demo 的 `TDEMOORDERS`）保持原来的全局 `data:create`，**不做数据迁移**（迁移会动到已有角色，风险大）。
代价：老表格在权限树里的按钮码是全局的，勾一次等于所有用默认码的表都开放；新建的表则是精确的。

- **A. 新表按 TCID，老表不动（推荐）**
- B. 老表也迁移成按 TCID（要同时改写所有角色的权限码，需要一次数据迁移脚本）

### ③ 权限树里「公开菜单」怎么显示？（推荐：显示但禁用）

- **A. 显示成灰色不可勾选，并标注「公开菜单（登录即可见）」（推荐）**
- B. 干脆不显示，只显示需要授权的菜单

### ④ JSON 配置注入给谁？（推荐：只给自定义页面）

- **A. 只注入 `CUSTOM` 页面（`props.routeConfig`）（推荐）** —— 表格页面本身不需要参数
- B. 表格页面也注入（那么 `<Table>` 要新增接收配置的能力，比如默认筛选值、默认每页条数）

### ⑤ 页签要不要缓存页面？（推荐：先不缓存）

- **A. 不缓存（推荐）**：切回页面会重新拉数据，实现简单、不会出现"看到旧数据"
- B. 加 keep-alive：切回不重新请求，但需要处理"数据该刷新时怎么刷新"

### ⑥ 自定义校验函数怎么存？（推荐：存名字，函数放前端源码）

需求里说"验证规则可自定义联动，返回一个 validate 函数"。
**如果直接把 JS 代码存进数据库并在前端执行，等于给后台开了任意代码执行的口子**（谁能配表格，谁就能在用户浏览器里跑任意脚本）。所以我改成：

- 正则：直接存正则字符串（安全）
- 自定义校验：只存**校验器名字**，真正的函数放 `client/src/components/table/validators.ts` 注册，函数签名 `(value, formModel) => 错误提示 | null`，能拿到整个表单，联动校验完全没问题

- **A. 正则 + 校验器注册名（推荐）**
- B. 坚持存 JS 代码字符串 —— 需要你明确接受这个安全风险（我会加超管限定 + 审计）

## 5. 验收标准（你确认后我按这个交付）

1. 打开「路由管理 → 编辑」，图标处点开是一个**网格弹层**，一行多个图标、能搜索、点击即选中。
2. 路由里设置「访问控制 = 按角色」，到「角色管理 → 编辑 → 权限」的**树里能勾到这条菜单**；不勾的角色登录后看不到该菜单。
3. 某 TABLE 路由下，权限树能看到该表的**新增/修改/删除/自定义按钮**，勾选后对应角色能操作数据。
4. 路由里填一段 JSON（如 `{"title":"订单中心"}`），自定义页面 `defineProps` 拿到 `routeConfig` 并在页面上显示出来。
5. 页面顶部出现**页签**：切换、关闭、关闭其它、关闭全部都正常，首页不可关。
6. 表格配置设计器：
   - 弹框更宽；
   - 字段可设「列表排序 / 搜索排序」，保存后表格列顺序、搜索项顺序按它排；
   - 字典编码是下拉；
   - 点「表单配置」弹出二级弹框，设置表单排序/显示/所占列/必填/校验规则；
   - 表单里按 24 栅格布局（12 就是一行两个），校验规则生效（手机号、邮箱填错会提示）。
7. 全量验证通过：后端 `build` + 单测、前端 `typecheck` + `build` + 单测、接口冒烟（TCID 建表/权限树/路由配置往返）。
