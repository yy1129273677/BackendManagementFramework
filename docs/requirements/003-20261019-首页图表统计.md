## 1. 我的理解

| 页面       | 改动                                                                                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 主系统首页 | 保留「平台总览」性质，**新增 ECharts 图表**（各子系统资源对比、表格配置分布）                                                                   |
| 子系统首页 | **只展示图表统计**：删掉「四步搭建步骤」「运行状态（后端/数据库/pgvector）」「常用入口」，换成数据量柱状图、角色用户饼图、近 7 天新增用户折线图 |

两个页面共用一套看板框架（统计卡片 + 图表卡片），按「当前在哪个系统」自动切换数据源。

---

## 2. 判定规则（视觉与数据口径）

1. **视角怎么判断**：`auth.isSuper && !auth.activeSystemCode` → 主系统视角；否则子系统视角。
   这样超管在顶栏切到某个子系统后，首页看到的是那个子系统的统计。
2. **主系统统计口径**：全平台聚合（所有子系统），仅超管可见（接口内部校验，普通用户 403）。
3. **子系统统计口径**：只统计当前子系统（`@SystemId()`），不跨租户。
4. **业务行数**：表 ≤ 30 张用 `count(*)` 精确统计；超过则用 `pg_class.reltuples` 估算并标注「估算」。
5. **近 7 天新增用户**：数据库只返回有数据的日期，前端图要连续，所以后端补 0。

## 7. 明确不做 / 边界

| 不做                             | 原因                                                |
| -------------------------------- | --------------------------------------------------- |
| 图表自动轮询刷新                 | 首页数据变化不频繁，手动刷新足够；轮询会白烧数据库  |
| 时间范围选择器（近 7/30 天切换） | 先固定 7 天，加筛选要把接口参数化，等有真实需求再做 |
| 导出图表图片 / 数据              | 不属于统计展示范围                                  |
| 图表点击下钻（点柱子跳列表）     | 可以做，但要和路由参数/筛选联动，另立需求           |
| 大表精确统计                     | 表多时用估算值并标注，避免首页变慢                  |
